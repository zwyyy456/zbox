# File Search 扫描、生命周期与路径去重（2026-10-15）

状态：实现及测量记录，非规范文档。产品与工程约定分别位于 `docs/product/file-search.md`、`engineering-guidelines.md`。

## 测量范围

新增 `script/benchmark_file_search_lifecycle.sh [文件数] [空闲采样间隔秒]`，默认生成 30,000 个真实临时文件（100 个目录，中英文混合名称、空正文），复用生产 Scanner、Store、Watcher，结束后删除临时目录。只扫描生成的目录，不扫描个人文件。

测量包括扫描期间的查询、索引 actor 状态读取等待、取消到任务退出的时间、快照保存、当前 RSS、physical footprint，以及另一个新进程中的快照打开、FSEvents 历史回放、首次查询。编译和创建测试目录不计入扫描耗时。文件刚创建，文件系统缓存可能命中；新进程启动不是磁盘缓存冷启动。进程内存是独立基准的内存，不是完整 zbox App 的内存。

基线压力测量刻意在 20 组查询完成后才保存快照，便于暴露大增量区的开销。最终生命周期测量改为扫描完成立即保存，与生产流程一致，并按查询开始时的 scanning/saving/ready 状态区分样本。因此不直接比较前后所有查询样本的总中位数；扫描实际耗时与查询工作集大小也会互相影响。

## 查询隔离及取消

Store 在 actor 内取得各根目录的不可变快照，搜索在后台任务中执行，调用方取消传递给后台任务。快照持有映射和增量的值视图；新变更由 Store 管理，旧查询可安全完成或取消。排序每 4096 次比较检查取消，扫描收尾的增量检查和删除循环也检查取消。

3 万文件压力基线中，索引状态读取中位等待为 56.98 ms、P95 为 107.72 ms；移出查询后，中位数降到 0.020 ms、P95 为 0.076 ms。取消任务退出中位数约 0.06 ms。快照写时复制没有在这组数据上造成明显内存增长，但不能据此推断百万文件并发写入的峰值。

## 批量目录读取

普通文件通过 `getattrlistbulk` 按目录批量取得名称、类型、修改时间、FinderInfo、隐藏标记与数据长度。目录、包、符号链接及特殊对象继续通过 Foundation 保持资源语义。错误导致扫描不完整，不触发未访问范围的清理。

实际核对 Darwin 缓冲区后确认：目录记录没有文件数据长度字段，不能将 `FSOPT_PACK_INVAL_ATTRS` 理解为所有对象都具有相同长度。解析检查返回属性集合、每项错误、字段和名称边界。行为依据 [Apple getattrlistbulk 手册源码](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/getattrlistbulk.2)。

在查询已移出 actor 的相同规模压力条件下，Foundation 扫描实际耗时约 3.55 秒，批量扫描约 0.55 秒。保持原查询隔离时的最初基线约 4.94 秒。以上是单次测量，不能将三者差异全部归因于目录读取。

元数据对照测试覆盖多批次读取、中文名称、隐藏属性、点文件、嵌套目录；既有测试覆盖包、符号链接、排除范围、浅扫描和目录替换。测试比较 Foundation 枚举结果时，必须将返回 URL 与根目录均规范化，否则临时目录别名会造成错误的相对路径切片。

## 路径去重

快照格式升级为 v4：每条记录从 56 字节变为 40 字节，只存名称编号、目录编号、大小、修改时间和类型。目录完整路径在目录表存一次；记录顺序仍按完整路径排序，子树查找保留二分范围定位。

名称与目录按原始 UTF-8 字节区分，避免 Unicode 规范等价但拼写字节不同的名称在重建路径时被替换。搜索比较仍按 NFC 语义。目录路径的规范等价查找可以收集多个原始拼写条目。时间戳按 Date 参考纪元保存，避免不必要的纪元转换损失小数精度。

旧快照不迁移，按现有可重建索引机制重新扫描；用户范围设置保留。

百万条不同名称的合成数据，快照从 171,681,538 字节降到 130,892,646 字节（约减少 23.8%）。最终修整后，总建库 6.30 秒（去重前 6.18 秒），快照保存 4.72 秒（之前 4.63 秒），峰值 RSS 456 MB（之前 479 MB），映射与校验 85 ms（之前 111 ms）。路径组合筛选 8.99 ms（之前 9.35 ms）。这些单次结果不表示建库加速；收益主要是文件体积与映射占用。构建过程仍需短暂持有用于排序的路径，不声称已彻底消除建库路径内存。

## 完整生命周期结果

`script/benchmark_file_search_lifecycle.sh 30000 30`：

| 指标 | 实测 |
| --- | ---: |
| 扫描实际耗时 | 554 ms |
| 快照保存 | 193 ms |
| 扫描期间查询（4 个样本） | 中位 161 ms，最大 233 ms |
| 已就绪查询（16 个样本） | 中位 1.81 ms，P95 2.38 ms |
| 索引状态读取等待（20 次） | 中位 0.020 ms，P95 0.098 ms |
| 取消到任务退出（20 次，均实际取消） | 中位 0.062 ms，P95 0.100 ms，最大 1.08 ms |
| 保存及查询后当前内存 | RSS 32.54 MB，footprint 20.04 MB |
| 空闲 30 秒当前内存 | RSS 9.57 MB，footprint 4.56 MB |
| 空闲 60 秒当前内存 | RSS 9.50 MB，footprint 4.56 MB |
| 新进程映射与校验 | 15.00 ms |
| 历史事件回放 | 21.54 ms，0 个变化目录 |
| 新进程首次查询 | 3.45 ms |

首次建库尚未发布快照时，增量查询仍是线性匹配。这组采样只能证明取消和 actor 竞争得到控制，不能证明大规模建库期间所有查询均为毫秒级；扫描期间只有 4 个样本，不对其 P95 作统计结论。首次建库或重建的较慢结果不再阻塞扫描和状态更新。

## 验证与边界

macOS 构建及 22 项文件搜索测试通过；最后对路径去重比较与哈希的修整另行通过 FileMappedIndexTests。覆盖原始 Unicode 路径字节、小数时间戳、并发查询期间移除根目录、取消、损坏快照、历史事件回放和批量扫描对照。

未运行 UI 测试；未人工验证完整 App 面板、外接卷、非 APFS 文件系统与系统级磁盘冷缓存；未把 3 万文件的真实扫描结果外推为百万文件扫描时间。现有百万条基准仍是元数据合成基准。

最后清理基准的冗余 await 后另做一次无空闲等待复测：扫描 562 ms、取消 P95 0.13 ms、新进程打开 4.95 ms、历史回放 18.02 ms、首次查询 0.86 ms，基准编译无警告。已就绪查询中位 4.50 ms；机器负载与缓存状态会影响小样本结果，保留两次测量而不选择性只报告较快值。
