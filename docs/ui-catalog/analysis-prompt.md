## 项目背景与既定约束

依据 `docs/product-design-v0.1.md` 第 1–4 节：zbox 是面向 macOS 开发者和效率工具重度用户的本地命令中心，用搜索和键盘完成应用启动、窗口和系统操作。用户通常熟悉 Spotlight、Raycast 或 Alfred，重视响应速度、可预测性与本地优先。并非复刻完整 Raycast 生态，未要求 AI 或云服务。

依据该文档第 1.1 节和 `engineering-guidelines.md`：最低 macOS 15，Swift 6、SwiftUI + AppKit，后台常驻、无 Dock 图标，菜单栏与全局快捷键打开主搜索；设置独立窗口。Root Search 和直接快捷键经同一 Command Registry 执行。插件设置独立，权限只在显式用户操作下请求。剪贴板采集默认关闭；取词不建立历史，截图不会为采集图册而自动上传。不要通过 UI 提案改变这些行为。

依据实际截图：01–02 是通用偏好与快捷键；03、04、07、09 是无条目的管理页；05、08、10 是未保存的新增表单；06、11–15 是关闭状态的文件、系统工具设置。22–25 已补拍剪贴板、截图、空白图床表单与取词设置。16–21、26 已验证侧栏、快捷键筛选与空状态的实际呈现。27–29 覆盖主搜索默认、键盘滚动与无匹配；30–31 覆盖计算器；33–38 覆盖开发工具五页及公开样例结果。权限相关插件运行状态仍未覆盖。

用户明确要求参考 HIG、Raycast、Alfred 并保持代码简洁。采用 macOS 原生侧栏、可筛选快捷键和明确空状态是本轮已实施且已截图核对的方向；具体字号、分组和间距不是 Apple 强制规范。真实使用频率、英文长文本和深色模式效果仍待核对。

## 参考与专项重点

可联网时查阅 Apple HIG 的侧栏、窗口、表单、菜单、键盘和无障碍规范，以及 Raycast / Alfred 官方文档。区分规范明确指导、平台惯例和设计建议，附直接链接；不能联网时标明未核实。

1. 寻找并配置工具：比较 01–15 的设置入口密度，检查分组侧栏能否让各插件可发现，避免用更多层级替代原本的一步入口。
2. 分配快捷键：比较 02 与 17–18，评估筛选、长命令名、错误反馈和录制控件的对齐；保留现有冲突处理。
3. 建立第一条内容：比较 03、04、07、09 与 19–21、26，判断空状态说明与添加按钮是否足够清楚；分开无数据、筛选无匹配和加载失败。
4. 编辑条目：比较 05、08、10，关注字段名称、变量说明、保存/取消层级和较长用户文本，避免为少数字段增加折叠或多步流程。
5. 设置与授权：查看 11、14、15，权限缺失应给出真实恢复入口；不要将未启用功能的操作伪装成可执行，也不要让权限按钮淹没主要任务。
6. 主搜索服务高频键盘操作：27–29 提供实际证据，键盘选到第 8 项时能滚入视野；错误恢复反馈仍未采集。请同时评价 30–38 的结果层级、输入标签、侧栏图标与空状态。
